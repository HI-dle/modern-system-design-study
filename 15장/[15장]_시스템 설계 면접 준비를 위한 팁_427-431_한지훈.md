# [15장]_시스템 설계 면접 준비

---

### 15.2 시스템 설계 면접을 위한 팁

- 면접관은 내가 모르는 문제를 낼 수 있다는 점을 전제로 깔고 간다.
- 당황하지 말고, 그동안 익힌 **핵심 개념, 구성 요소, 설계 철학, 기법, 서브시스템**을 새롭게 조합하면 대부분 풀어낼 수 있다.

#### 15.2.1 문제 정의 제대로 하기

- 설계에 들어가기 전에 문제를 정확히 이해하는 데 먼저 시간을 쓴다.
- **명확하지 않은 부분은 질문한다**
   - 범위, 제약 사항, 애매한 점을 적극적으로 확인한다.
   - 예: 채팅 앱 설계라면 실시간 메시징이 중심인지, 사용자 인증이나 메시지 저장이 중요한지 먼저 확정한다.
- **기능적 요구 사항 정리**
   - 시스템이 반드시 갖춰야 할 핵심 기능을 정리한다.
   - 예: 전자 상거래 플랫폼 → 회원 가입, 상품 검색, 장바구니, 결제
- **비기능적 요구 사항 파악**
   - 성능, 확장성, 가용성, 신뢰성 등을 반드시 짚는다.
   - 예: 소셜 미디어 피드 → 읽기·쓰기 요청이 매우 많으므로 낮은 지연 시간이 필요하다.

#### 15.2.2 문제를 쪼개서 접근

- 복잡한 문제일수록 다루기 쉬운 작은 단위로 나눠서 푼다.
- **컴포넌트 파악**
   - 전체 시스템을 구성하는 핵심 컴포넌트/서비스를 먼저 뽑는다.
   - 예: URL 단축 서비스 → API 게이트웨이, URL 저장소, 리디렉션 서비스, 통계 분석 서비스
- **컴포넌트 간 상호 작용 정의**
   - 각 컴포넌트가 어떻게 연결되고 데이터를 주고받는지 정리한다.
   - 예: API 게이트웨이가 단축 요청 수신 → 저장소에 원본 URL과 단축 URL 매핑 저장 → 리디렉션 서비스가 요청을 분석해 원래 주소로 안내
- **다이어그램으로 시각화**
   - 블록 다이어그램, 시퀀스 다이어그램으로 설계 구조를 전달한다.
   - 예: 사용자 → API 게이트웨이 → 저장소 → 리디렉션 서비스로 이어지는 데이터 흐름을 도식화한다.

#### 15.2.3 단계별 핵심 단계

1. **기능적 요구 사항 작성**
   - 꼭 필요한 핵심 기능부터 정리한다. 부가 기능이나 사용 사례를 억지로 늘리지 말고 핵심 흐름에 집중한다.
   - 면접관에게 요구 사항을 확인받으면서 방향을 잡는다.
2. **비기능적 요구 사항 정리**
   - 자주 쓰이는 비기능적 요구 사항을 먼저 나열하고, 현재 문제와 관련 있는 것을 체크하는 식으로 접근한다.
   - "고가용성이어야 한다"처럼 모호하게 말하지 않고 **99.9%, 99.99%** 같은 수치로 말한다.
   - "일관성이 중요하다" 대신 **어떤 상황에서 어떤 수준의 일관성**이 필요한지 말한다.
3. **API 목록 정리**
   - 사용자에게 노출되는 API뿐 아니라 시스템 내부에서 필요한 API까지 정리한다.
   - 앞서 정리한 기능 요구 사항을 구현하는 흐름을 기준으로 뽑는다.
   - REST API 형태를 권장하지만 함수/메서드 수준으로 적어도 된다.
4. **고수준의 시스템 규모 산정**
   - 숫자 맞추기로 끝내지 않고, 계산 결과가 **설계 결정을 뒷받침하는 근거**가 되게 한다.
   - 10의 거듭제곱에 가까운 수로 단순화한다. (예: 하루 86,400초 → 10만 초로 가정)
5. **상위 수준의 블록 다이어그램 그리기**
   - 클라이언트, 로드 밸런서, 애플리케이션 서버, 마이크로서비스, DB 등 핵심 구성 요소 중심으로 전체 구조를 그린다.
   - 전체 흐름을 그려 두면 **병목 지점, 단일 장애 지점**과 핵심이 될 부분이 보인다.
6. **핵심 과제를 짚고 넘어가기**
   - 병목 지점이나 구조적 한계를 짚고 이를 해결하도록 설계를 다듬는다.
   - 면접관의 힌트를 놓치지 말고, 내가 짚은 이슈를 더 깊이 파도 되는지 반응을 보며 논의를 이어 간다.
7. **최종 아키텍처 다이어그램 완성**
   - 초기 블록 다이어그램을 보완해 최종본을 만든다.
8. **요구 사항 충족 여부 점검**
   - 설계한 시스템이 기능적/비기능적 요구 사항을 모두 충족하는지 확인하며 마무리한다.

#### 15.2.4 해결 방안을 효과적으로 전달

- 설계 내용을 **얼마나 명확하게 전달하느냐**가 설계 자체만큼 중요하다.
   - 아이디어가 뛰어나도 설명이 부족하면 강점이 전달되지 않는다.
   - 반대로 설계가 단순해도 사고 과정과 결정을 깔끔하게 전달하면 좋은 평가를 받는다.

- **체계적으로 설명하기**
   - 문제 제시 → 큰 틀의 설계 방향 → 주요 구성 요소 → 각 선택의 장단점 순으로 논리적 흐름을 따른다.
   - 시스템 목표에서 시작해 아키텍처, 구성 요소 세부 사항과 상호 작용 순으로 내려간다.
- **핵심 결정 사항과 이유 설명하기**
   - 특정 DB나 캐싱 전략을 골랐다면 왜 그것이 요구 사항에 가장 적합한지 반드시 말한다.
   - 이 부분이 **주니어와 시니어를 가르는 차이**가 되기도 한다.
- **면접관의 힌트와 질문 의도 잘 듣기**
   - 설계 면접은 면접관과 협력하는 과정이다. 면접관이 특정 방향으로 유도하면 캐치해서 맞춰 간다.
- **피드백 듣고 설계 개선하기**
   - 한 번에 완벽하게 완성하려 하지 말고, 피드백을 받아 단계적으로 발전시키는 자세를 보여 준다.
- **말로만 하지 말고 글과 그림 활용하기**
   - 머릿속으로만 생각하지 말고 말로 설명하면서 동시에 적는다.
   - 다이어그램, 블록 그림, 흐름도를 적극적으로 그린다.
- **마지막에 간결하게 요약하기**
   - 고수준 아키텍처와 주요 구성 요소를 다시 정리한다.
   - 강점과 함께 **트레이드오프, 한계**도 솔직히 말하면 신뢰감이 올라간다.
- **후속 질문에 대비하기**
   - 구성 요소, 알고리즘, 설계 판단의 근거를 구체적으로 설명할 준비를 한다.
   - 특히 **확장성 유지 방법**과 **장애 상황 처리**는 거의 반드시 추가 질문이 들어온다.
- **경험을 적극적으로 활용하기**
   - 받은 문제가 이전 프로젝트와 비슷하면 연결 지어 설명한다.
   - 무엇이 효과적이었고 어디서 어려움을 겪었는지 나누면 설득력이 올라간다.
- **다른 요구 사항도 놓치지 않기**
   - 동작 여부만이 아니라 **신뢰성, 관측 가능성, 디버깅 편의성, 사용성**도 챙긴다.
   - 생각해 두었다가 적절한 시점(주로 면접 후반부)에 꺼내면 운영 측면까지 고민하는 지원자로 보인다.

- 정리하면 설계를 잘 설명하는 능력은 기술적 이해도를 넘어, 타인과 협력하고 복잡한 내용을 명확하게 전달하는 역량을 보여 준다.
- 이 소통 능력은 당락뿐 아니라 **어떤 직급과 역할을 맡게 될지**에도 큰 영향을 준다.

### 15.3 요약

- 시스템 설계 면접은 소프트웨어 엔지니어, 엔지니어링 관리자의 **고위 직책**을 맡는 데 매우 중요하다.
   - 얼마나 확장 가능하고 효율적이며 견고한 구조를 설계할 수 있는지 평가한다.
   - 좋은 성과를 내면 합격을 넘어 더 높은 직급, 더 많은 책임과 보상으로 이어질 수 있다.

#### 면접 준비

- 시스템 설계의 **기본 개념**부터 철저히 이해한다.
   - 주제: 확장성, 데이터베이스, 캐싱, 일관성 모델
   - 설계 패턴: 마이크로서비스, 이벤트 기반 아키텍처, SOA
- **모의 면접, 설계 과제**로 꾸준히 연습하고 실제 시스템 사례 연구를 분석한다.

#### 자료 활용

- 책, 온라인 강의, 기업 블로그, 유튜브 채널 등에서 업계 최신 사례와 모범 사례를 꾸준히 익힌다.
- 설계 결정을 명확하게 전달하는 연습을 하고, 복잡한 아이디어를 그림이나 차트로 간결하게 설명하는 능력을 기른다.

#### 면접 진행 중

- 문제를 완벽하게 이해하는 데 집중한다.
   - 구체적인 질문으로 요구 사항을 파악하고, 기능적/비기능적 요구 사항을 모두 짚는다.
- 문제를 해결 가능한 작은 구성 요소로 나누고, 상호 작용을 정의한 뒤 도식화해 전달한다.
- 발표를 논리적으로 구성하고 주요 결정 사항을 강조하며, 면접관의 피드백에 따라 유연하게 설계를 조정한다.

- 정리하면 **이론적 지식, 실무 경험, 효과적인 의사소통 능력** 세 가지가 결합돼야 시스템 설계 면접에서 좋은 성과를 낼 수 있다.
- 시스템 설계는 지속적으로 학습하고 발전해야 앞서갈 수 있는 분야다.
