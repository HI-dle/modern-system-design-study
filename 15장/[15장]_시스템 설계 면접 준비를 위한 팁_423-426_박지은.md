- 시스템 설계 면접: 시니어 소프트웨어 엔지니어, 엔지니어링 매니저 등 시니어 레벨 채용 과정의 핵심 단계.
  - 실제 서비스 설계 시 겪는 복잡성과 현실적인 어려움을 얼마나 잘 이해하는지 평가.
  - 이를 바탕으로 확장성과 효율성을 동시에 만족하는 시스템 구조를 만들 수 있는지 평가.
- 단순히 합격 여부만 결정하지 않음.
  - 가능성과 잠재력을 보여 주면 연차와 상관없이 더 좋은 대우 가능.
  - ➡️ 설계 역량에 따라 더 넓은 책임과 권한, 그에 걸맞은 처우.
- 이 장에서 다루는 내용
  - 시스템 설계 면접을 준비하는 방법
  - 시스템 설계 면접을 위한 팁

# 15.1 시스템 설계 면접을 준비하는 방법

- 이론적인 지식 + 실제 경험 + 이를 명확하게 전달하는 커뮤니케이션 능력 ➡️ 함께 키워야 함.

## 15.1.1 기본 개념부터 확실히 익히기

- 기초가 튼튼하면 처음 접하는 문제나 예상치 못한 질문에도 핵심을 빠르게 파악하고 해결 가능.
- 확장성
  - 수평 확장성과 수직 확장성의 개념, 로드 밸런싱, 분산 시스템.
  - 로드 밸런서가 네트워크 트래픽을 여러 서버에 고르게 분산 ➡️ 특정 서버의 과부하 방지하는 원리.
- 데이터베이스
  - SQL과 NoSQL의 차이, 인덱싱, 샤딩, 데이터베이스 레플리카.
  - PostgreSQL 같은 관계형 DB와 MongoDB 같은 비관계형 DB를 상황에 따라 언제 사용할지 구별.
- 캐싱
  - 여러 캐싱 전략과 캐시 삭제 정책, 레디스나 멤캐시드 같은 툴 사용.
  - 자주 사용하는 데이터를 레디스에 캐싱 ➡️ 데이터베이스 접근 감소 ➡️ 성능과 응답 속도 향상.
- 일관성과 가용성
  - CAP 정리와 PACELC 정리, 강한 일관성과 최종 일관성.
  - 분산 환경에서 일관성과 가용성 사이의 상충 관계.
- 이것만으로 모든 주제를 다룰 수는 없지만, 책 앞부분을 꼼꼼히 읽었다면 이미 충분히 접한 내용.

## 15.1.2 자주 쓰는 시스템 설계 패턴 학습

- 자주 등장하는 설계 패턴과 활용법 ➡️ 설계 질문을 받았을 때 좋은 인상.
- 마이크로서비스 아키텍처
  - 시스템을 작은 서비스 여러 개로 나누고, 서비스끼리 어떻게 소통하는지 이해.
  - 일반적으로 RESTful API나 gRPC로 마이크로서비스 간 통신 구현.
- 이벤트 기반 아키텍처
  - 메시지 큐나 이벤트 스트림을 이용해 이벤트 발생 시 시스템이 반응하도록 설계.
  - 실시간 데이터 처리 파이프라인에 아파치 카프카 같은 도구 활용.
- 서비스 지향 아키텍처(Service-Oriented Architecture, SOA)
  - 마이크로서비스와 SOA의 차이 및 각각 적합한 경우 이해.
  - 오래된 기존 시스템과 통신하거나 강력한 계약(contract) 관리가 필요할 때 SOAP를 많이 사용.
- 디자인 패턴
  - CQRS(Command Query Responsibility Segregation), Saga 패턴, 서킷 브레이커 등.
  - 서킷 브레이커 패턴 ➡️ 분산 시스템에서 장애 발생 시 안정적으로 처리.

## 15.1.3 시스템 설계 연습

- 직접 설계하면서 익혀야 실력이 늚 ➡️ 이론적 지식 강화 + 문제 해결 능력 향상.
- 확장성 좋은 웹 애플리케이션부터 데이터베이스 설계까지 여러 경우를 접하며 연습.
- 모의 면접
  - 프램프(Pramp), Interviewing.io, Exponent 같은 모의 면접 서비스 활용 또는 지인과 모의 면접 스터디.
  - 예: URL 단축 서비스 같은 문제로 설계 연습 ➡️ 피드백을 받아 부족한 부분 보완.
- 설계 연습
  - 릿코드(LeetCode), 해커랭크(HackerRank), Grokking the System Design Interview 같은 자료 참고.
  - 확장 가능한 알림 시스템, 차량 호출 서비스 같은 실전 문제 연습.
- 실제 사례 분석
  - 운영 중인 서비스의 아키텍처와 설계 결정 과정을 추론.
  - 예: X(전 트위터)의 아키텍처를 분석하며 대규모 처리량과 낮은 지연 시간 유지 방법 연구.
- 꾸준한 연습과 반복 리뷰 ➡️ 설계 원칙에 대한 이해 심화 + 효율적·안정적·관리 용이한 시스템을 만들 수 있다는 자신감.

## 15.1.4 온라인 자료로 학습

- 온라인 자료나 강의 활용 ➡️ 이해 심화 + 최신 트렌드와 실무 사례 학습.
- 도서
  - 마틴 클레프만 <데이터 중심 애플리케이션 설계>(위키북스, 2018)
  - 마틴 L. 애벗, 마이클 T. 피셔 <The Art of Scalability(확장성 아키텍처 설계의 기술)>(Addison-Wesley Professional, 2015)
  - 대규모 시스템을 안정적이고 확장성 있게 만드는 데 필요한 깊이 있는 내용.
- 온라인 강의
  - Coursera, Udemy, Educative 같은 플랫폼.
  - Educative의 Grokking the System Design Interview ➡️ 실무에 바로 적용 가능한 설계 원칙과 패턴을 명확히 설명, 면접 준비에 도움.
- 블로그 및 뉴스 기사
  - 뛰어난 시스템 아키텍처로 유명한 기업·엔지니어의 블로그 팔로우 ➡️ 실무 레벨의 고민과 해결 방식 학습.
  - 넷플릭스, 우버, 링크드인 개발 블로그 ➡️ 실제 사례와 노하우 공유.
- 유튜브 채널
  - Tushar Roy, Tech Dummies, Gaurav Sen 등.
  - 시스템 설계 개념을 구체적이고 쉽게 설명, 면접 팁과 실무 팁도 함께 제공.
- 방대하고 깊이 있는 분야 ➡️ 한 가지 방법에만 의존하지 말고 여러 자료로 꾸준히 학습.

## 15.1.5 커뮤니케이션 역량 늘리기

- 면접에서 생각을 명확하게 전달하려면 효과적인 커뮤니케이션 능력이 가장 중요.
- 생각을 말로 풀어내는 연습
  - 평소 문제를 풀어 나가는 방식을 입으로 설명하는 연습.
  - 친구나 동료와 모의 면접을 하며 각 설계 결정을 어떻게 내렸는지 조리 있게 설명하는 데 집중.
- 시각 자료 활용
  - 복잡한 구조나 흐름 설명 시 그림 활용.
  - 아키텍처 다이어그램, 시퀀스 다이어그램을 그리며 설명하는 연습 ➡️ 듣는 사람이 훨씬 쉽게 이해.

## 15.1.6 복기 및 피드백

- 실제 면접이든 모의 면접이든 끝나면 반드시 복기하고 개선점 찾기.
- 스스로 점검하기
  - 잘한 점과 부족한 점 돌아보기.
  - 요구 사항을 빠짐없이 다루었는지, 중요한 구성 요소를 놓치지 않았는지 확인.
- 피드백 받기
  - 동료, 멘토, 면접관 등 여러 사람에게 요청.
  - 접근 방식, 커뮤니케이션 방식, 기술적 깊이 등을 구체적으로 피드백받기.
- 지속적으로 개선하기
  - 피드백을 바탕으로 방향성 재점검, 약한 부분 집중 보완.
  - 예: 데이터베이스 설계에 약했다면 관련 아키텍처를 더 공부하고 문제를 반복해서 풀기.

- 시스템 설계 면접 준비 요약
  - 이론적 지식, 실전 감각, 커뮤니케이션 역량을 고르게 갖추기.
    - 기본 개념 이해
    - 주요 설계 패턴 학습
    - 꾸준한 연습과 체계적인 접근
    - 온라인 자료 적극 활용
    - 의사소통 역량 다듬기
  - 많이 연습하며 스스로 점검하고 개선하는 자세 ➡️ 복잡한 문제를 자신감 있게 유연하게 풀어내는 밑거름.
